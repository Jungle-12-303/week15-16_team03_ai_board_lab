# Troubleshooting

## 기본 확인 명령

```bash
docker compose ps
docker compose logs -f
docker compose logs -f backend
docker compose logs -f nginx
docker compose logs -f db
```

## 1. 백엔드가 DB에 연결하지 못할 때

증상:

- backend 로그에 `Connection refused`
- `FATAL: password authentication failed`

확인:

```bash
docker compose ps
docker compose logs -f db
```

해결:

- `.env`의 `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` 확인
- 이미 만들어진 DB volume에 예전 비밀번호가 남아 있으면 `docker compose down -v` 후 재실행

## 2. pgvector extension 오류

증상:

- `type "vector" does not exist`
- `CREATE EXTENSION vector` 실패

원인:

- 일반 postgres 이미지를 사용했거나 pgvector가 없는 DB를 사용한 경우

해결:

- `docker-compose.yml`의 DB 이미지가 `pgvector/pgvector:pg16`인지 확인

## 3. RAG 결과가 비어 있을 때

가능한 원인:

- 작성된 게시글이 없음
- 게시글 작성 시 embedding 저장이 실패함
- DB에 pgvector extension이 없음

확인:

```sql
select count(*) from posts;
select count(*) from post_embeddings;
```

해결:

- 게시글을 2개 이상 작성
- backend 로그에서 `RAG_INDEX` 실패 확인

## 4. OpenAI API가 없어도 동작하는 이유

`OPENAI_API_KEY`가 비어 있으면 백엔드는 로컬 해시 기반 임베딩과 fallback 요약을 사용합니다. 이 방식은 실제 AI 품질을 대체하기 위한 것이 아니라 API 키 없이도 RAG/Agent 흐름을 데모하기 위한 안전장치입니다.

## 5. MCP GitHub 호출 실패

증상:

- MCP 응답에 error가 포함됨
- GitHub rate limit 또는 username 오류

확인:

```bash
docker compose logs -f backend
```

해결:

- username 확인
- 필요하면 `.env`에 `GITHUB_TOKEN` 설정

## 6. 프론트에서 API 호출이 실패할 때

증상:

- 브라우저에서 로그인/게시글 요청 실패
- CORS 오류

해결:

- 로컬 Vite 개발 서버는 `/api`를 `http://localhost:8080`으로 proxy합니다.
- Docker 환경에서는 Nginx가 `/api`를 backend로 proxy합니다.
- 직접 백엔드에 접근할 때는 `CORS_ALLOWED_ORIGINS`에 프론트 주소를 추가합니다.

## 7. EC2에서 접속이 안 될 때

확인:

- EC2 보안 그룹에서 80 포트 허용
- `docker compose ps`에서 nginx 컨테이너 실행 여부 확인
- 서버 방화벽이 있다면 80 포트 허용

명령:

```bash
curl -I http://localhost
curl -I http://서버공인IP
```
